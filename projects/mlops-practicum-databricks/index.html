Project Case Study

MLOps Practicum - Databricks

A hands-on MLOps practicum testing Databricks across AWS, Azure, GitHub Actions, and Azure DevOps.

This practicum focused on investigating the MLOps and CI/CD capabilities of Databricks in public cloud environments. I collaborated with a Fortune 500 financial services cloud engineering team to evaluate whether Databricks was a strong fit across AWS and Azure, using a financial fraud detection workflow as the practical test case.

The work progressed in clear stages: first exploring the platform and tools such as MLflow, then integrating Databricks with AWS and Azure, then building CI/CD paths with GitHub Actions and Azure DevOps, and finally pushing toward a more automated fraud-model deployment flow. That made the project valuable because it tested Databricks not just as a notebook environment, but as a realistic collaboration layer for machine learning engineering work.

A big part of my contribution was making the findings usable. I delivered biweekly sprint reports and presentations that summarized how Databricks performed in terms of scalability, cost efficiency, performance, and usability. Alongside the technical work, I used those updates to turn experimentation into clearer platform recommendations instead of leaving the project as a loose collection of notebook results.

Highlights

  • Collaboration: Worked with a Fortune 500 financial services cloud engineering team to evaluate Databricks across AWS and Azure environments.
  • Use case: Anchored the work around example financial fraud detection pipelines instead of a generic platform demo.
  • CI/CD implementation: Built and documented delivery flows using both GitHub Actions and Azure DevOps, then connected those pipelines to model experimentation and deployment work.
  • MLOps workflow: Used Databricks features such as MLflow, model management, and model serving to evaluate how well the platform supports iterative model change over time.
  • Reporting: Delivered biweekly sprint reports and presentations covering scalability, cost efficiency, performance, and usability.

Further Direction

The team identified a few important areas that remained unfinished because of time and resource constraints. These included deeper work with SQL Warehouse for large-scale analysis, more sophisticated model workflows, and a more complete weekly retraining and serving loop using feature tables and automated model updates.

That future work matters because it would move the project from a strong practicum into a more complete production-style MLOps pipeline. In that sense, the project was valuable not only for what it implemented, but for clarifying which pieces of Databricks-based automation are straightforward and which still require more engineering maturity.
